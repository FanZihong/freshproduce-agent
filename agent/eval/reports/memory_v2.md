# Memory v2：事实老化与过期清理

- 生成时间：2026-10-20 09:55:16
- 演示会话：`memory-v2-demo`（临时库，不碰正式数据）
- 参数：TTL **30 天**、半衰期 **14 天**、最低权重 **0.5**

## 一、老化系数曲线

`decay = floor + (1 - floor) × 0.5^(age / half_life)`

| 距上次使用 | 老化系数 |
| --- | --- |
| 0 天 | 1.0000 |
| 7 天 | 0.8536 |
| 14 天 | 0.7500 |
| 30 天 | 0.6132 |
| 60 天 | 0.5256 |
| 180 天 | 0.5001 |

## 二、同样的相关性，新旧事实的排序变化

两条事实的可召回性被打平（同一向量、同样命中查询词），唯一差别是**上次被用到的时间**：

| 事实 | 距上次使用 | 老化系数 | 不降权排名 | 降权后排名 |
| --- | --- | --- | --- | --- |
| 旧：草莓坏果一半已赔付 | 25 天 | 0.6450 | #1（0.0664） | #2（0.0428） |
| 新：草莓坏果一半待赔付 | 1 天 | 0.9758 | #2（0.0661） | #1（0.0645） |

结论：降权前旧事实排第一，降权后新事实反超——旧事实分数从 0.0664 降到 0.0428，但没有被清零：高度相关的旧记忆仍有机会靠相关性赢回来。

## 三、TTL 清理

- 过期阈值：30 天（`MEMORY_FACT_TTL_DAYS`）
- 过期事实：1 条（用户问过发票抬头怎么开，40 天未用）
- 清理结果：删除 1 条；索引 3 → 2 条
- 清理后再召回：未召回

读时过滤保证「即使没跑到清理，过期事实也不会被召回」；`purge_expired_facts` 负责真正删库，并同步删向量，避免幽灵向量。

## 五、决策

- 老化只改**排序**，不改 `vector_score`：注入门槛看相关性，避免「新但无关」的记忆挤掉「旧但命中」的记忆；
- 半衰期 14 天、floor 0.5：指数部分每两周减半（叠加 floor 后 1.0 → 0.75），最低保留一半，防止长期未用的事实被永久埋没；
- 事实 TTL 30 天（摘要 7 天）：售后跟进常跨月，事实比摘要更长寿；被召回一次就会续期；
- 默认 `MEMORY_RECALL=off`：机制与门禁都就绪，等真实 trace 消融再决定是否打开。
