# 进化层报告：数据飞轮 + 评测门禁

> 生成时间：2026-10-19
> 结论先说：**飞轮转起来了，但它是"半自动"的**——信号自动挑、门禁自动判，
> 中间的"这条到底是不是错"仍然由人确认。这一层真正立得住的东西不是"AI 自己进化"，
> 而是**"任何改动都必须先过门禁"**这条纪律，以及为了让这条纪律可执行而建的整套工具。

## 一、飞轮的四环

| 环节 | 落地形态 | 输入 → 产出 | 谁在做 |
| --- | --- | --- | --- |
| 采集 | `scripts/run_cli.py` 每轮落 trace | 对话 → `data/trace/*.jsonl` + `sessions`/`messages` 表 | 自动 |
| 挖掘 | `scripts/mine_traces.py`（8 个信号） | trace → `eval/datasets/trace_badcase_pool.jsonl` | 自动挑、**人工判定** |
| 反哺 | 意图 `evolve_intent.py --source pool` / 知识库 `update_knowledge.py` / 检索 `iterate_rerank.py` | 标注结果 → 训练数据 / 知识库条目 / 检索配置 | 脚本 + 人工 |
| 门禁 | 意图 `evolve_intent.py --gate` + 全链路 `scripts/regression.py` | 候选版本 → 通过/拒绝 | 自动 |
| 发布 | `scripts/release.py` | 两道门禁 → `data/intent/active.json` | 自动，可 `--rollback` 一键回滚 |

## 二、真实发生过的四个案例

### 案例 1｜v2 被门禁拒掉（门禁存在的意义）

v2 换了 catalog 提示词、max_len 放到 640，整体看着还行，但关键类崩了：

| 指标 | v1（现役） | v2（候选） | Δ | 判定 |
| --- | --- | --- | --- | --- |
| macro-F1 | 0.7366 | 0.7085 | −0.0281 | ✗ |
| quality_qa F1 | 0.5155 | 0.5347 | +0.0192 | ✓ |
| chitchat F1 | 0.6010 | 0.6352 | +0.0342 | ✓ |
| human_handoff F1 | 0.6176 | 0.3111 | **−0.3065** | ✗ |

结论：**保留 v1**。这个案例是整个自进化层最有力的证据——如果没有门禁，
v2 会因为"两个短板类涨了"被当成进步上线，而转人工识别会直接掉一半。

### 案例 2｜第一批 trace 信号全是噪声（信号要区分"不确定"和"正常"）

第一次跑挖掘：10 轮对话 / 6 个会话，挖出 5 条候选，其中 4 条是**补槽位轮**
（用户回"2026093000123""大概一半""照片传不上来"这类碎片，规则版把它们打成 chitchat、置信度 0.35）。
但这些轮次的路由由"续接未完成流程"接管，标签根本不影响结果，回复也都对。

修法：把"已有槽位 + 兜底标签 + 未转人工"的轮次从低置信信号里排除，但仍如实统计"跳过 N 轮"；
加 `--include-slot-turns` 可放回来。修完：5 条 → 2 条真候选。

顺带发现：这 2 条人工标注后，**都与模型当时的判定一致**——它们是正样本，不是错例。
所以这一轮飞轮转完，能改进模型的东西是 0 条。这不是工具的问题，是**数据量的问题**。

### 案例 3｜知识库补 6 条，检索指标 +1 条 query

用 `--probe` 主动问 13 个业务问题，5 条判"无据"，补成条目后（追加到文件末尾）：

| 指标 | 补之前 | 补之后 | Δ |
| --- | --- | --- | --- |
| recall@5（生产口径） | 0.8333 | 0.8667 | +0.0333 |
| recall@1（生产口径） | 0.4167 | 0.4500 | +0.0333 |
| MRR（生产口径） | 0.6178 | 0.6578 | +0.0400 |
| 未命中 | 5 条 | 4 条 | −1（q017「生鲜可以无理由退货吗」修好） |

**插曲（这次最有价值的教训）**：第一版脚本是"插到对应小节的末尾"。规则分块的 chunk id 是
文件内全局序号，往"受理范围"插 1 条，后面所有条目整体后移一位，
黄金集里按 id 写的期望值全部错位——recall@5 掉到 0.8000，看着像检索退化，其实一条内容都没变。
修法：默认改成**追加到文件末尾的「补充问答」小节**，只新增编号、已有条目 id 不动。
这件事说明门禁不只防"模型变差"，也防"评测自己失真"。

### 案例 4｜检索路 A/B：有收益，但端到端看不见

用错例当靶子对比混合路与纯向量：

| 配置 | recall@5 | recall@1 | MRR | 未命中 | 救回当前错例 |
| --- | --- | --- | --- | --- | --- |
| hybrid+rw+score（现役） | 0.8667 | 0.4500 | 0.6578 | 4 | — |
| vector+rw（纯向量） | 0.9000 | 0.5000 | 0.7028 | 3 | 2（q001、q014；新丢 q007） |

但把 `RETRIEVAL_KIND=vector` 接进图之后跑端到端：判据通过率 1.0、目标解决率 1.0、
误转率 0、工具成功率 0.9667、judge 达成率 1.0 / 与人工一致率 0.9——**与混合路完全一致**。

原因：向量救回的是 q001（坏了一点点可以赔吗）、q014（分量少了 10% 能赔多少），
属于赔付档位类；而对话黄金集里的 FAQ 只有 4 段，一条都不落在这个类别上。
**结论：净收益存在，但现有端到端评测覆盖不到它**——这暴露的是评测集的缺口，不是检索的问题。

## 三、决策日志（这一层定下来的口径）

1. **防泄漏**：badcase 只从 dev 挖，test 锁死做验收；想用 test 必须显式 `--allow-test-leakage`，
   报告里会写明这属于自欺欺人。线上 trace 是新数据，不涉及泄漏。
2. **门禁口径**：意图层 macro-F1 与三个关键类（quality_qa / chitchat / human_handoff）都不劣化；
   全链路 17 个指标按各自容差判（意图 ±0.01，对话 1 段≈0.034，时延用相对 25%）。
3. **知识库补条目默认追加到末尾**：chunk id 稳定性优先于"按主题摆放好看"；
   要按主题插中间，脚本会警告"后面的 id 会整体后移、黄金集需重标"。
4. **不做全自动上线**：闭环 = 数据飞轮 + 评测门禁，"跑几小时训练"交回给人，
   但"能不能上"由门禁自动判、由 `release.py` 自动切。
5. **影子对比 ≠ 真灰度**：单机没有流量分流，我们做的是"新旧版本跑同一份评测出对比卡"，
   它提供决策依据，但不提供流量隔离；这句话必须写进任何对外材料里。

## 四、局限（不藏）

- **半自动**：信号只负责挑可疑轮次，真值靠人；这一轮 2 条标注全是正样本，错例量是 0。
- **端到端评测覆盖不足**：对话集对"检索路"这个变量不敏感，案例 4 的收益在端到端不可见。
- **误杀与漏检仍在**：域外召回 0.88（目标 0.9）、知识库"有据但答非所问"的门槛盲区，
  目前只能靠 judge 层兜。
- **没有真实流量**：所有"灰度"都是影子对比。

## 五、简历素材（三条，可直接复述）

1. **"搭了一条 trace → badcase → 三路反哺 → 评测门禁 → 发布/回滚的自进化闭环，
   任何改动必须过门禁才能上线；用真实案例证明门禁拦下过一个关键类 F1 掉 0.31 的版本。"**
2. **"用错例驱动优化：从 trace 挖候选、人工确认后分别反哺意图训练集、知识库、检索配置；
   知识库补 6 条让 recall@5 从 0.8333 提到 0.8667，并定位到『往中间插条目会导致 chunk id 漂移、
   把评测标注打偏』这个隐蔽问题。"**
3. **"评测驱动的诚实结论：检索路 A/B 显示纯向量在检索层更优（0.8667→0.90），
   但端到端零差异；据此判断是评测集覆盖不足而非改动无效，并把它写进报告而不是硬说成收益。"**

复现命令：

```bash
# 采集 → 挖掘 → 标注 → 反哺
python scripts/run_cli.py --turns "..."
python scripts/mine_traces.py
python scripts/evolve_intent.py --export --source pool
python scripts/update_knowledge.py --probe "..." && python scripts/update_knowledge.py --apply
python scripts/iterate_rerank.py --refresh

# 门禁 → 发布 → 回滚
python scripts/release.py --candidate data/intent/models/v3
python scripts/release.py --rollback
```
